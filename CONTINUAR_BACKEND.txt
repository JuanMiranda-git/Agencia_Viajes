2. BLOQUEO ACTUAL: ACCESO A MYSQL
--------------------------------------------------------------------------------
Sintomas observados:
  - `mysql -u root -p`                      -> ERROR 1045 Access denied (using password: YES)
  - `mysql -u root` (sin -p)                -> ERROR 1045 Access denied (using password: NO)
  - `sudo mysql`                            -> ERROR 1045 (root NO usa auth_socket)
  - `mysql -u tourmanager -p314159265`      -> ERROR 1045 (el usuario aun no existe)
  - `sudo -n mysql`                         -> sudo pide contrasena (no hay NOPASSWD)

Diagnostico: en Ubuntu 24.04, MySQL 8.0.46, el usuario root@localhost NO usa
autenticacion por socket; usa caching_sha2_password con una contrasena que no
conocemos. Ademas el usuario de la app 'tourmanager' todavia no ha sido creado.
El servicio mysqld SI esta corriendo (proceso /usr/sbin/mysqld).

Conclusion: hay que recuperar acceso a MySQL y crear el usuario antes de poder
importar el esquema y ejecutar la prueba E2E.

3. TUTORIAL PASO A PASO (DESDE CERO)
--------------------------------------------------------------------------------

### PASO 1. Preparar el entorno
  Abrir terminal en:
    /home/miranda/Documentos/LIt_/Code/VSC/AgenciaViajes/BACKEND
  Verificar Node y dependencias:
    node --version
    npm ls

### PASO 2. Diagnostico de MySQL (opcional, para confirmar acceso)
    id
    sudo -l
    mysql --version
    ps aux | grep -E '[m]ysqld|[m]ariadbd'

### PASO 3. Recuperar acceso a MySQL (root con contrasena desconocida)
  Detener el servicio e iniciar mysqld SIN control de privilegios:

    sudo systemctl stop mysql
    sudo mkdir -p /var/run/mysqld
    sudo chown mysql:mysql /var/run/mysqld
    sudo mysqld --skip-grant-tables --user=mysql --daemonize

  Conectar sin contrasena:
    mysql -u root

  Dentro del prompt `mysql>`, crear la base y el usuario de la aplicacion:
    CREATE DATABASE IF NOT EXISTS tourmanager
      CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
    CREATE USER IF NOT EXISTS 'tourmanager'@'localhost' IDENTIFIED BY '314159265';
    GRANT ALL PRIVILEGES ON tourmanager.* TO 'tourmanager'@'localhost';
    FLUSH PRIVILEGES;
    exit;

  (Opcional: si tambien quiere restablecer la clave de root)
    ALTER USER 'root'@'localhost' IDENTIFIED BY 'CLAVE_NUEVA_DE_ROOT';
    FLUSH PRIVILEGES;
    exit;

  Volver al servicio normal:
    sudo mysqladmin shutdown        # si falla: sudo pkill mysqld
    sudo systemctl start mysql
    sudo systemctl status mysql     # debe quedar "active (running)"

### PASO 4. Importar el esquema
    mysql -u tourmanager -p314159265 tourmanager \
      < /home/miranda/Documentos/LIt_/Code/VSC/AgenciaViajes/BACKEND/database/datos_agencia_viajes.sql

  Si el script intenta crear la BD y faltan privilegios (ya la creamos en el paso 3):
    mysql -u tourmanager -p314159265 tourmanager \
      -e "SOURCE /home/miranda/Documentos/LIt_/Code/VSC/AgenciaViajes/BACKEND/database/datos_agencia_viajes.sql;"

### PASO 5. Verificar acceso de la aplicacion
    mysql -u tourmanager -p314159265 -e "SHOW TABLES FROM tourmanager;"
  Debe listar las 24 tablas del esquema.

### PASO 6. Ejecutar el servidor
    cd /home/miranda/Documentos/LIt_/Code/VSC/AgenciaViajes/BACKEND
    npm start
  Esperado: "TourManager API escuchando en http://localhost:3111 (entorno: development)"
  Apagado ordenado: Ctrl+C (SIGINT) cierra el pool de conexiones.

### PASO 7. Pruebas E2E (una por una; anotar el codigo HTTP de cada una)

  7.1 Salud (espera 200 con baseDatos: ok):
    curl -s -w "\nHTTP %{http_code}\n" http://localhost:3111/api/v1/salud

  7.2 Login Administrador (espera 200 + token). Copiar el <TOKEN>:
    curl -s -X POST http://localhost:3111/api/v1/autenticacion/iniciar-sesion \
      -H 'Content-Type: application/json' \
      -d '{"email":"admin1@tourmanager.com","contrasena":"Admin123*"}'

  7.3 Listar paquetes (espera 200):
    curl -s -H "Authorization: Bearer <TOKEN>" http://localhost:3111/api/v1/paquetes

  7.4 Crear reserva (espera 201). Anotar el idReserva devuelto:
    curl -s -X POST http://localhost:3111/api/v1/reservas \
      -H "Authorization: Bearer <TOKEN>" -H 'Content-Type: application/json' \
      -d '{"idPaquete":1,"idCliente":1,"fechaViaje":"2026-12-15","numPasajeros":2}'

  7.5 Confirmar reserva (espera 200 y numero AV-YYYYMMDD-XXXX):
    curl -s -X POST http://localhost:3111/api/v1/reservas/<ID_RESERVA>/confirmar \
      -H "Authorization: Bearer <TOKEN>"

  7.6 Registrar venta (espera 201). Anotar el idVenta:
    curl -s -X POST http://localhost:3111/api/v1/ventas \
      -H "Authorization: Bearer <TOKEN>" -H 'Content-Type: application/json' \
      -d '{"idReserva":<ID_RESERVA>,"monto":3700000,"metodoPago":"Transferencia"}'

  7.7 Comprobantes PDF (espera 200 y archivos PDF):
    curl -s -o /tmp/comprobante-reserva.pdf -w "HTTP %{http_code}\n" \
      http://localhost:3111/api/v1/reservas/<ID_RESERVA>/comprobante \
      -H "Authorization: Bearer <TOKEN>"
    curl -s -o /tmp/comprobante-venta.pdf -w "HTTP %{http_code}\n" \
      http://localhost:3111/api/v1/ventas/<ID_VENTA>/comprobante \
      -H "Authorization: Bearer <TOKEN>"

  7.8 Reglas de negocio (esperan 422):
    - Venta sobre reserva NO confirmada.
    - Reservar paquete inactivo.
    - Transporte con proveedor sin contrato vigente (RN-02).
    - Inactivar un rol con usuarios activos.

  7.9 Login Cliente y sus propias reservas (espera 200):
    curl -s -X POST http://localhost:3111/api/v1/autenticacion/iniciar-sesion \
      -H 'Content-Type: application/json' \
      -d '{"email":"cliente@tourmanager.com","contrasena":"Cliente123*"}'
    curl -s -H "Authorization: Bearer <TOKEN_CLIENTE>" \
      http://localhost:3111/api/v1/reservas/mis-reservas

### TABLA DE PROBLEMAS COMUNES
  | Sintoma                              | Causa probable                     | Solucion                                  |
  |--------------------------------------|------------------------------------|-------------------------------------------|
  | Access denied con tourmanager        | Usuario no creado / clave distinta | Repetir PASO 3 desde `mysql -u root`      |
  | Access denied con root -p            | root no usa auth_socket            | PASO 3 (skip-grant-tables)                |
  | baseDatos: error en /salud           | MySQL detenido o credenciales mal  | `sudo systemctl status mysql`; revisar .env|
  | Puerto 3111 en uso                   | Otro proceso escucha               | Cambiar PUERTO en BACKEND/.env            |
  | 401 en endpoints protegidos          | Falta token Bearer                 | Hacer login y copiar el token             |
  | 503 en cualquier endpoint            | BD caida o sin importar            | PASO 4 (importar esquema)                 |
