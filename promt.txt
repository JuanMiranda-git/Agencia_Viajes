ARCHITECTURE CONTEXT
The central rule is the separation of responsibilities: each layer only
talks to the next one.

Real order of a request
1. index.js: starts the process, verifies the MySQL connection and handles
   the server shutdown.
2. config/express.js: creates the app and registers CORS, JSON parsing,
   logger, routes and error handling.
3. routes/index.js: mounts /api/v1 and delegates to the router of each entity.
4. routes/*.routes.js: declares verb + URL + middlewares + controller.
5. controllers/*.controller.js: extracts params/query/body, calls the
   service and builds the HTTP response.
6. services/*.service.js: validates, applies business rules, queries the
   database and returns domain objects.
7. models/*.js: represent a row as an object (private attributes,
   getters/setters and toJSON).
8. config/database.js: MySQL pool and parameterized queries.

middleware/ and utils/ are cross-cutting: errors, logs, parameter
validation, authentication/authorization (JWT and roles), responses,
dates, formatting, constants and AppError.

Responsibility of each layer
- routes: contain no logic; they only connect a URL to a controller and
  its middlewares.
- controllers: thin; they write no SQL and apply no business rules.
- services: the only place with SQL and business rules; they use
  db.ejecutar / obtenerUno / conTransaccion.
- models: know nothing about HTTP or MySQL; they run no queries.
- database: knows nothing about Express or the domain.

Example (adapt to the real entities found in /context): POST /api/v1/clientes
routes/cliente.routes.js -> clienteController.crear
-> cliente.service.js crear() normalizes, validates, instantiates Cliente
   and runs the INSERT
-> models/Cliente.js represents the result and its toJSON()
-> the controller responds 201 with respuesta.creado() and a Location header.

   - One ES6 class per domain entity (e.g., Cliente, Reserva, Paquete,
     Destino, Pago), with constructors, field validation, and a method to
     serialize to JSON. Keep them independent from the database layer.
     The reserved parameters for each class must be assigned using '#'
     followed by the parameter name in camelCase.
   - Each model exposes getters/setters and toJSON(); it does not know
     HTTP or MySQL and does not execute queries.

C3 – Layered architecture
   - Strict separation: no SQL in controllers/routes, no business logic in
     models, no HTTP objects (req/res) in services.
   - The flow is always routes -> controllers -> services -> models/database.
   - Routes contain no logic; controllers are thin; services are the only
     place with SQL and business rules; the database layer does not know
     Express or the domain.

C4 – REST API design
   - Versioned base path (/api/v1), plural resource names, correct HTTP
     verbs and status codes, pagination/filtering on list endpoints,
     and a uniform error response format.
   - Successful responses use the envelope { ok, mensaje, datos, meta }
     built exclusively through utils/respuesta.js.

C5 – Data access
   - Only `mysql2/promise` with a pool and placeholders; the pool config
     comes from environment variables; handle connection errors and
     release connections properly.
   - Every query uses `?` placeholders and a parameters array; never
     concatenate values into SQL.

C6 – Request flow and responsibility of each layer
   - Implement the request flow and the layer responsibilities described
     in ARCHITECTURE CONTEXT.
   - Controllers and services are exported as singletons:
     module.exports = new X().
   - When adding an entity, create its model, service, controller and
     router, then mount the router in routes/index.js.
   - Locate the correct layer first, according to the responsibility of the
     change, before writing code.

C7 – Rules that must never be broken
   - The flow is routes -> controllers -> services -> models/database.
   - No controller writes SQL; no model knows HTTP.
   - Errors are thrown with AppError and handled by
     middleware/errorHandler.js.
   - Async handlers are wrapped with capturarAsync.
   - Services filter fields with whitelists and map camelCase (API) to
     snake_case (database columns).
   - Keep Spanish in code, comments, messages and documentation. Write
